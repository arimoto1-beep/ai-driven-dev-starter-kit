# core: 作業メモ

## このファイルの目的

作業の経緯・判断・手戻りを、結果だけでなく後から確認できる形で残すための、
プロジェクトに依存しない原則を定めます。

## このファイルを読む作業

- 作業メモを新規作成・更新する作業
- 作業メモの作成候補を判断するとき
- 作業完了報告で作業メモ作成を提案するかどうか判断するとき

## このファイルに含めないもの

- 保存場所、フォルダ命名、README必須項目の具体値 → `docs/rules/project/60_work_notes.md`
- 作業メモの作成条件（トリガー）の具体値 → `docs/rules/project/60_work_notes.md`
- AIが作業メモを作成・更新してよい条件の具体値 → `docs/rules/project/50_ai_permissions.md`、`docs/rules/project/60_work_notes.md`
- 現在地メモ（`tasks.md`）・作業完了報告・レビュー補助メモとの書き分け → `50_records_and_reporting.md`
- 正式資料と補助記録の区別の定義そのもの → `40_official_docs_and_context.md`

## ルール

### 作業メモの位置づけ

作業メモは、作業時点の経緯・判断・問題・手戻り・現在地・引き継ぎ事項を残す記録です。

次のいずれの正本でもありません。

- 正式仕様
- 設計書
- ルール
- `tasks.md`
- レビュー結果
- 承認結果

現在有効な内容は、それぞれ所定の正式文書を確認する必要があります。

**作業メモと正式文書が矛盾した場合、AIは勝手にどちらかを採用せず、人間確認事項として報告します。** この扱いは `40_official_docs_and_context.md` の原則と同じです。ここで再定義しません。

### 結果だけでなく経緯を残す

次の内容を、最終結果に不要という理由で削除しません。

- 作業上のミス
- 見落とし
- 誤った前提
- 手戻り
- AIの報告と実際のファイル状態との差異
- GO判定後に判明した問題
- 修正後に見つかった別の不整合
- 途中で変わった判断
- 採用しなかった案とその理由
- 調査中に見つかった別問題
- 再現できなかった問題
- 原因を確定できなかった問題
- 確認できなかった事項
- 人間が判断したこと
- 次回の作業者に注意してほしいこと

これらは、経緯を復元するために記録価値のある情報であり、体裁のために省略してよい項目ではありません。

### 個人評価にしない

ミスや問題を記録する場合、個人の能力評価や責任追及を目的としません。

次を中心に記録します。

- 何が起きたか
- どの時点で分かったか
- どのような影響があったか
- どのように対応したか
- 現在の状態
- 次回の注意点

次は書きません。

- 感情的な評価
- 個人を責める表現
- 事実確認できていない責任帰属

### 事実・推測・未確認を区別する

作業メモは正式仕様ではありませんが、実際に起きたことの記録として正確性を求めます。**分類上「提案・補助記録」であることは、正確性の要求を下げる理由になりません。**

次を区別して記載します。

- 確認した事実
- 推測
- 未確認

原因を確定できなかった場合は、推測で確定させず、確定できなかったこと自体を記録します。

### READMEと詳細記録の分離

README.md は、作業フォルダの入口・現在地・索引です。

- 詳細な作業経緯を README だけで代替しません。
- 付随ファイルにある詳細を、短い要約だけに置き換えて削除しません。
- ただし、README へ結論や現在地を簡潔に重ねて記載することは妨げません。

同じ詳細説明を複数ファイルへ別々に管理することは避けますが、**README の短い説明と付随ファイルの詳細という役割の異なる重複は禁止しません。**

### Gitや完成物との関係

次のような強い禁止はしません。

- Gitから復元できる情報は作業メモへ書いてはいけない
- 完成物に存在する情報は作業メモへ書いてはいけない

代わりに、次の方針とします。

- Git差分やテストログの全文を、理由なく複製しません。
- ただし、経緯の理解に必要な変更内容、確認結果、現在の状態は記録します。
- **Gitや完成物だけでは分からない判断理由、迷い、手戻り、却下理由は特に残します。**
- 元の情報を再確認できる場合は、参照先や実行方法を示します。

### 完了後の記録

完了後は、過去の経緯を現在の結論に合わせて消さないことを原則とします。

- 後から判明した事実は、原則として日付付きで追記します。
- **明白な誤記や事実誤認は、人間の明示指示がある場合に訂正できます。**
- 訂正時は、何を訂正したかと理由が分かる形を残します。
- 履歴として必要な過去の事実を削除しません。

「人間が指示してもAIは絶対に書き換えてはならない」という扱いにはしません。訂正の可否と手順は、人間の判断と明示指示に従います。

### 報告と保存の区別

AIが作業完了報告をチャットへ出力することと、リポジトリ内へ作業メモとして保存することは別です。

**作業完了報告を出しただけでは、AIが作業メモを新規作成・更新してよいことにはなりません。** 新規作成・更新の条件は `docs/rules/project/50_ai_permissions.md` と `docs/rules/project/60_work_notes.md` に従います。
