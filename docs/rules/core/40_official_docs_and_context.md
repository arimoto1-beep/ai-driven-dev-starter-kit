# core: 正式資料と補助コンテキスト

## このファイルの目的

何が現在の仕様・設計・運用の正本で、何がそうでないかを区別します。
AIが補助的な記録を確定仕様として扱わないための基準を定めます。

## このファイルを読む作業

- 補助コンテキストを確認する作業
- レビュー作業
- バグ調査
- 文書を作成・更新する作業

## このファイルに含めないもの

- **成果物の具体的な一覧と、どの成果物がどの分類かの割り当て** → `docs/rules/project/10_document_structure.md`
- 補助コンテキストの具体的な置き場 → `docs/rules/project/10_document_structure.md`
- テンプレート対応表と、文書種別ごとの見出し運用の具体 → `docs/rules/project/15_document_templates.md`
- AIがどのファイルを更新してよいか → `docs/rules/project/50_ai_permissions.md`
- 現在地メモ・作業完了報告・レビュー補助メモの書き分け → `50_records_and_reporting.md`

## ルール

### 正式資料の定義

```text
正式資料とは、現在の仕様・設計・運用を定義する正本として、
プロジェクトが明示的に指定した成果物である。
```

次は正式資料に多く見られる**特徴**ですが、**定義条件ではありません**。

- ひな形がある
- レビュー対象である
- 承認境界を持つ

したがって、ひな形のない新しい設計資料、承認欄を持たない横断設計、正式な利用手順として扱う文書も、プロジェクトが正本として指定していれば正式資料です。

**一覧にない成果物を、AIが独断で「正式資料ではない」と判断してはなりません。**
判断できない場合は、人間確認事項として報告します。

### 成果物の3分類

成果物は、次の3種類に分けて扱います。プロジェクトごとの具体的な割り当ては `docs/rules/project/10_document_structure.md` にあります。

| 分類 | 位置づけ | 扱い |
|---|---|---|
| **正本** | 現在の仕様・設計・運用を定義する成果物 | 常に基準とする。変更は上流から順に反映する |
| **正式な管理記録** | 正式な工程で作成されるが、現在の仕様そのものを定義するわけではない記録 | 工程の証跡として尊重する。ただし仕様の根拠としては正本を参照する |
| **提案・補助記録** | 判断材料、過去情報、未確定事項、提案などを保持する記録 | 確定仕様として扱わない。確認トリガーとして参照する |

正本と正式な管理記録を混同しないでください。
レビュー結果や判定記録は正式な工程の産物ですが、それ自体が現在の仕様を定義するわけではありません。

### 補助コンテキストの扱い

- **提案・補助記録は確定仕様ではありません。** そのまま仕様・設計・実装方針として採用してはなりません。
- 正本とのズレ・矛盾・反映漏れ・未決事項・却下案の混入を検出するための**確認トリガー**として参照します。
- レビュー・調査では正本を基準とし、補助記録は補助資料として扱います。
- **正本と矛盾する場合、AIは勝手にどちらかを採用せず、人間確認事項として報告します。**
- AIが判断できない内容は、確定仕様とせず人間確認事項として扱います。

### 横断探索を主責務にしない

- 補助記録の横断的な探索を、通常のレビューや調査の主責務にしません。
- 補助記録の量が増えても、通常のレビューや調査を完遂できるようにするためです。
- 深掘りが必要な場合は、専任の作業へ委譲します。

### 過去の記録の扱い

- 過去の判断・会議メモ・過去の作業記録から見つけた内容を、**現在の正本として扱いません**。
- 提示する際は、確定なのか、未決なのか、却下されたのかを区別します。
- 過去の記録にない内容を補完して、確定事項にしません。

### 文書の型

「テンプレートの定義」と「テンプレートを使って作る個別の成果物」を区別します。

**AIは、テンプレートファイルそのものや、テンプレートとして定義された標準構成を勝手に変更しません。**

**正本・正式な管理記録**を作成する場合は、**標準構成の見出しを維持します。** 情報がない場合も見出しを削除せず、`未定`、`該当なし`、`確認中`、`人間判断待ち` のような状態を記載します。検討漏れと証跡の欠落を防ぐためです。

**提案・補助記録**を作成する場合は、プロジェクトのルールが許可している範囲で、**個別成果物の中で該当しない見出しを省略してかまいません。** 読みやすさを優先するためです。

**この省略は、テンプレート定義自体の変更とは扱いません。** テンプレートファイルにも標準構成にも手を加えないためです。逆に、テンプレートファイルや標準構成そのものを変更する場合は、成果物側の判断ではなく、人間の明示指示による変更作業として扱います。

その他:

- **ファイル自体を形式的に空で作成しません。** まだ必要のない成果物は、無理に作成しません。
- ひな形のない成果物が必要になった場合、AIは新しいひな形を勝手に作らず、追加候補として人間判断へ回します。

分類ごとの具体的な適用と、省略してよい範囲は `docs/rules/project/15_document_templates.md` にあります。

### 補助記録から正式資料への反映

- 補助記録の内容を正本へ反映する場合は、**別の正式な変更作業**として扱います。
- 採用・却下・保留は人間が判断し、採用された分だけを反映します。
- 反映先の特定と反映順は `10_workflow.md` の「変更の正本と上流からの反映」に従います。
