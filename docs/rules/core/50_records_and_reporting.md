# core: 記録と報告

## このファイルの目的

AIが残す記録を目的ごとに書き分け、同じ内容を複数の記録へ重複させないための境界を定めます。

## このファイルを読む作業

主に**作業完了時**に読みます。作業開始時に読む必要はありません。

- 成果物を作り終えて報告するとき
- 現在地メモを更新するかどうか判断するとき
- レビュー補助メモを書くとき

## このファイルに含めないもの

- どのファイルをAIが直接更新してよいか（工程別の可否） → `docs/rules/project/50_ai_permissions.md`
- 現在地メモやレビュー結果の配置 → `docs/rules/project/10_document_structure.md`
- 正式資料と補助記録の区別 → `40_official_docs_and_context.md`
- 各作業の報告項目の細目 → 対応する `prompts/*.md`
- 作業メモの原則 → `60_work_notes.md`
- 作業メモの保存場所・運用の具体値 → `docs/rules/project/60_work_notes.md`

## ルール

### 記録の種別と境界

| 記録 | 時間軸 | 目的 | 書かないもの |
|---|---|---|---|
| **現在地メモ** | 今の進捗 | 作業の中断・再開・引き継ぎ | 仕様・設計・テスト計画の内容、レビュー判定、詳細な指摘 |
| **作業完了報告＋レビュー補助メモ** | 今からの確認 | 人間がレビューに入る前の申し送り | 合否判定、思考過程や試行錯誤のログ |
| **作業メモ** | 作業時点の経緯（開始から完了後まで） | 判断・手戻り・現在地を後から追えるようにする引き継ぎ記録 | 正式仕様・設計・ルール・`tasks.md`・レビュー結果・承認結果の代わりとなる内容 |

この3つを無理に統合しません。目的と読み手が異なります。作業メモの原則は `60_work_notes.md`、このスターターキットでの保存場所・作成条件・運用は `docs/rules/project/60_work_notes.md` を正本とします。ここには複製しません。

### 現在地メモ

- 作業を中断・再開・引き継ぎしやすくするため、現在の状態・次にやること・保留事項を**短く**記録します。
- **現在地メモを、仕様・設計・テスト計画・レビュー結果の代わりにしません。**
- レビューの判定や詳細な指摘を、現在地メモに書きません。判定は判定用の成果物に記録します。

### AIが直接更新してよい成果物

- **AIが直接更新してよい成果物と、候補提示に留める成果物は、プロジェクトが工程ごとに定めます。**
- 直接更新しない成果物について更新が必要と判断した場合は、勝手に更新せず、**更新候補として作業報告に記載**します。実際の反映は人間が判断します。

### 作業完了報告

作業完了時に、次を報告します。

- 変更したファイルと、その理由
- 実装または作成した内容
- 実施した検証の内容と結果（**再現できる形で記載する**）
- 上流資料との整合確認の結果
- 未対応事項・残課題
- 更新しなかった資産がある場合、**更新不要と判断した理由**（省略しない）

**作業完了報告をチャットへ出力することと、その内容をリポジトリ内へ作業メモとして保存することは別です。** 作業完了報告を出したことだけをもって、AIが作業メモを新規作成・更新してよいことにはなりません。保存の可否は `60_work_notes.md` と `docs/rules/project/50_ai_permissions.md`、`docs/rules/project/60_work_notes.md` に従います。

`docs/rules/project/60_work_notes.md` が定める作成候補の条件に該当する場合、AIは作業完了報告の中で**作業メモ作成の提案**を行えます。提案はチャット出力であり、ファイル操作ではありません。

### レビュー補助メモ

レビュー補助メモは、AIが成果物を作り終えたときに、人間レビューを速くするために作業完了報告へ添える短い申し送りです。

**AIの思考過程や試行錯誤の記録ではありません。** レビュー判断に必要な結論だけを短く残します。

次の5項目を簡潔に記載します。該当がない項目は「なし」と書きます。

1. 判断が分かれそうだった点
2. 採用した判断と理由
3. 採用しなかった案
4. 仮置きした前提
5. 人間に確認してほしい点

記載ルール:

- 各項目は数行までにとどめ、結論を箇条書きで書きます。検討の経緯や試行錯誤のログは書きません。
- **レビュー補助メモに合否判定を書きません。** 判定は判定用の成果物の領分です。
- レビュー補助メモは作業完了報告として出力します。現在地メモには書きません。レビュー補助メモ専用のファイルも作りません。
