# project: プロジェクト方針

## このファイルの目的

このプロジェクトの識別情報と、プロジェクト設定の索引をまとめます。
作業開始時に最初に読むファイルです。

## このファイルに含めないもの

- 共通原則そのもの → `docs/rules/core/` の各ファイル
- 具体的なディレクトリ、工程、実装規約、権限 → 下記索引の各ファイル

## プロジェクト識別

| 項目 | 現行値 |
|---|---|
| プロジェクト名 | ai-driven-dev-starter-kit |
| 種別 | CLIアプリケーション（AI駆動開発を小さく体験するためのスターターキット） |
| 開発方針文書 | `docs/concept/ai_driven_development.md` |
| 想定する成果物 | コマンド/アプリ単位の docs / src / tests 一式 |

作業を開始する前に、開発方針文書を確認してください。
このプロジェクトでは、AIに任せても人間が理解・レビュー・引き継ぎ・責任を持てる形にすることを重視しています。

## core / project / task の関係

```text
core     AI駆動開発を安全に進めるための共通原則（docs/rules/core/）
project  core を、このプロジェクトでどう具体化するかを定義する初期設定（このディレクトリ）
task     個別工程で何を行い、何を出力し、どこを変更してよいかを定義する（prompts/*.md）
```

- **project は core を無効化または緩和しません。** core を具体化します。
- **task も、core と project の範囲内で実行します。**
- project または task が core と矛盾して読める場合、AIは勝手にどちらかを採用しません。人間確認事項として報告します。
- 参照先が見つからない場合も、推測で進めず人間へ確認します。

## 利用者が編集するのは、このディレクトリです

- `docs/rules/core/` はキットの共通原則です。**利用者が通常変更する場所ではありません。**
- **このディレクトリの設定が core を無効化することはできません。** core を具体化するだけです。
- `docs/rules/project/` は**現行スターターキットの値が記入済み**です。空欄はありません。
- そのまま利用できます。プロジェクトの事情と異なる箇所だけを書き換えてください。

### 変更が project 配下だけで完結しない場合があります

| 種類 | 変更範囲 |
|---|---|
| **通常の project 設定** | このディレクトリの変更だけで完結する（想定読者、実装言語、テストコマンド、ディレクトリ構成、AI更新権限、承認欄の場所 など） |
| **キット本体との同期変更が必要な設定** | プロンプト・テンプレート・集計ツールが同じ値に依存している（レビュー結果ラベル、判定結果の出力形式、テンプレートとプロンプトの対応、集計ツールが解析する固定値） |

後者を変更する場合、**このディレクトリだけを変更して完了とはしません。** 依存するキット本体の変更を、別の正式な変更作業として同時に行います。

- **AIが勝手にキット本体を変更しません。** 変更対象と影響範囲を整理し、人間の承認後に別作業として実施します。
- 通常の project 設定であっても、変更前に「他ファイルが同じ値に依存していないか」を確認してください。

同期対象の具体例は `25_review_policy.md` の「ラベルを変更する場合」と、`15_document_templates.md` の「テンプレートを変更する場合の注意」にあります。

## プロジェクト設定の索引

| ファイル | 何を決めるか | 変更頻度 |
|---|---|---|
| `10_document_structure.md` | どこに何を置くか（成果物の分類と一覧、ディレクトリ、命名、保存先） | 中 |
| `15_document_templates.md` | どのひな形を使うか（テンプレート対応、文書種別ごとの見出し運用） | 中 |
| `20_workflow.md` | どの順番で進めるか（標準工程、承認を置く工程、各種フロー） | 中 |
| `25_review_policy.md` | レビュー結果の評価値と品質運用（集計ツールとの関係を含む） | 中 |
| `30_development_rules.md` | 何で作るか（言語、依存、実装規約、責務分担） | **高** |
| `40_testing_rules.md` | どう検証するか（試験の単位、実行コマンド、配置） | **高** |
| `50_ai_permissions.md` | AIにどこまで許すか（保護対象、更新権限、承認欄の場所） | 中 |
| `60_work_notes.md` | 作業メモの保存・構成・運用（保存場所、記録対象と粒度の決定主体、AI権限） | 中 |

言語やテスト方法が異なるプロジェクトでは、まず `30_development_rules.md` と `40_testing_rules.md` を確認してください。

**`GO` / `条件付きGO` / `STOP` は共通で固定されており、このディレクトリでは変更できません**（`docs/rules/core/20_approval_and_review.md`）。変更できるのはレビュー結果の評価値の側です。

## 記録に含める情報の範囲

このスターターキットは汎用の配布物です。そのため、次を守ります。

- **このスターターキットの配布物には、特定の会社・案件・担当者・社内用語・内部管理番号を含めません。**

この制約は、キットを汎用のまま配布するためのものです。
**実際のプロジェクトで、必要な案件情報を成果物へ書くこと自体は禁止しません。** その場合は、この項目をプロジェクトの実情に合わせて書き換えてください。

なお、「今回の作業と無関係な案件・組織・会話の文脈を持ち込まない」という原則は core 側にあります（`docs/rules/core/30_change_safety.md`）。こちらは書き換えの対象ではありません。
