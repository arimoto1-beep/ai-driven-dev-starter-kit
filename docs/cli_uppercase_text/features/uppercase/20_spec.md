# 機能名

uppercase

## 作りたいもの

入力された1件の文字列を、大文字へ変換して返す feature です。CLI引数解析や標準出力は担当しません（`docs/cli_uppercase_text/10_overview.md` の責務・Boundaryに従います）。

## 実行イメージ

```python
uppercase("Hello 123")
```

## 期待する出力

```text
"HELLO 123"
```

## 必須要件

要件には `REQ-001` 形式のIDを振ります。IDは、設計・テスト観点・レビューから参照する識別子です。

- 各要件は、**観測可能な形で検証できる**書き方にします
- **一度振ったIDは変更・再利用しません。** 要件を削除する場合も、IDを他の要件へ付け替えません
- 要件の削除は、保証範囲の縮小に当たります。AIが単独で行いません（`docs/rules/project/70_feature_loop.md`）

- REQ-001: 文字列を1件受け取り、Python の `str.upper()` 相当で大文字へ変換した文字列を返す
- REQ-002: 空文字列 `""` を入力として許可し、`""` を返す

## 入力

- str 型の文字列を1件

## 出力

- 大文字変換後の str 型の文字列

## エラー扱い

- 今回は対象外。入力が文字列以外の場合の挙動や独自エラー処理は「今回やらないこと」に含む

## 今回やらないこと

- CLI entrypoint の実装
- ファイル入力
- 複数文字列の一括変換
- 入力が文字列以外の場合の変換や独自エラー処理
- locale 固有の変換ルール
- GUI
- 外部API
- CI/CD
- デプロイ

## レビュー観点

- 要件があいまいすぎないこと
- 入力と出力が明確であること
- 正常系と異常系が想像できること
- 今回やらないことが明記されていること
- 単体試験までの範囲に収まっていること

## 補足

- Boundary: 入力は Python の `str`、出力も Python の `str` とする。feature は文字列変換だけを担当し、入出力処理は持たない（`docs/cli_uppercase_text/10_overview.md` の Boundary をそのまま踏襲）。
- 本 feature は `10_overview.md` に記載された唯一の feature であり、責務・利用イメージ・今回やらないことは、同ファイルの記述をそのまま整理したものである（新たな仕様の発明ではない）。
