# docs/context/ai_work_logs/（AI作業ログ）

このディレクトリは、AIに何を依頼し、AIが何を確認し、何を更新し、何を更新しなかったのかを、後から追えるようにするための補助コンテキストです。

`docs/context/` 配下のサブディレクトリのため、基本的な位置づけは [docs/context/README.md](../README.md) に準じます。

---

## 目的

- AIに何を依頼したかを記録する
- AIが何を確認したか（参照したファイルなど）を記録する
- AIが何を更新し、何を更新しなかったかを記録する
- 更新しなかった場合は、その理由を記録する
- 実行した確認（テスト実行結果など）と、残課題・未確認事項を記録する

これにより、後から人間がAIの作業内容を追跡し、作業を引き継ぎやすくすることを目的とします。

---

## 重要：AI作業ログは正式仕様ではありません

- AI作業ログは正式仕様ではありません。
- `docs/context/` 配下の他のメモと同じく、AIにとっては**確認トリガー**であり、確定仕様として扱いません。
- AI作業ログの内容を、そのまま仕様・設計・実装方針として採用してはいけません。
- 確定事項は、`20_spec.md`、`21_design.md`、`23_test_plan.md`、`25_review_result.md`、`12_command_review_result.md` など、正式資料へ別作業として反映してください。
- 正式資料と矛盾する内容がAI作業ログにある場合、AIは勝手にどちらかを採用せず、人間確認事項として報告します。

---

## 記録する内容

AI作業ログには、次のような内容を記録します。

- AIに依頼した内容
- AIが確認したファイル
- AIが更新したファイル
- AIが更新しなかったファイル
- 更新不要と判断した理由
- 実行した確認（テスト実行結果など）
- 残課題・未確認事項

ひな形は [docs/templates/ai_work_log_template.md](../../templates/ai_work_log_template.md) を使用してください。

---

## ファイル名

ファイル名は、日付・対象タスク・短いタイトルが分かる形にします。

```text
YYYYMMDD_<task_id>_<short_title>.md
```

例:

```text
20260704_T-001_update_review_results.md
```

---

## AIの基本ルール

- AIは、人間の明示指示なしに AI作業ログを勝手に作成・更新しません。
- AI作業ログに書いた内容を、確定仕様として扱いません。
- 正式反映が必要な内容は、仕様書・設計書・テスト計画・レビュー結果などへ、別作業として反映します。
- AIが判断できない内容は、確定仕様とせず人間確認事項として扱います。
