## 判断に迷ったもの

### 1. `docs/tutorials/030` の手順（243行・260行）を書き換えるか

**書き換えないと判断しました。**

題材の `cli_text_counter` は `24_review_checklist.md` に「実装開始条件」節を持たないため、
`70_feature_loop.md` の後方互換規定により `manual` として扱われます。したがって手順自体は現行仕様と
矛盾していません。

矛盾しているのは「読者が一般則として受け取りうる」点だけなので、**手順は残し、前提を1文で明示**
する方法を採りました。手順を書き換えると、マニュアルモードのチュートリアルとしての流れが壊れます。

### 2. `docs/overview.md` の節見出し「実装前承認ゲート」を改名するか

**改名しないと判断しました。**

`auto` でも実装前に人間の承認（CP1 仕様承認）は存在するため、見出し自体は両方式を包含できます。
リポジトリ内から他ファイルの参照もありません（`docs/overview.md:116` のみ）。
Phase 1 は誤りの是正が目的なので、見出し変更は行いませんでした。

### 3. テストへ `10_document_structure.md` を追加するか

**追加すると判断しました。**

計画（`03_execution_plan.md`）に明記していない作業ですが、次の理由で Phase 1 の範囲内と判断しました。

- 対象一覧に1行追加するだけで、テストのロジックも他ファイルも変えない
- **既存テストの対象漏れが、`g0` の例が残っていた直接の原因**である
- Phase 1 の完了条件「現行資料に `G0` の例が残っていない」を恒久化できる

新規ファイルへスコープを広げる変更ではないため、実施しました。
