## 最初の一歩の説明

READMEだけを読んだ人が、次の流れとして理解できる構成にしました。

```text
人間が 20_spec.md（仕様）を用意する
        ↓
AIが仕様をレビューする（何度でも実行できる）
        ↓
★ 人間が仕様を承認する                … CP1
        ↓
AIが設計する                           … G1
        ↓
AIがテスト設計をする                    … G2
        ↓
AIが実装・テストを作り、レビューする      … CP3
        ↓
★ 人間が受け入れを判断する              … CP3
        ↓
      完成
```

図の直後に、次の4点を補足しています。

- **最初の入力は `20_spec.md`**
- **人間が必ず止まるのは CP1 と CP3 の2か所**
- 各段階でAIは Worker と Reviewer に分かれる
- `CP1` / `G1` / `G2` / `CP3` は呼び名であり、**覚えなくても流れは追える**

コマンドは `feature_runner.py --help` と `tools/README.md` を確認し、**実在するものだけ**を書いています
（`--spec-review` / `--dry-run` / `--status` と、オプションなしの実行）。

## 判断に迷った点

### 1. 流れの図に `G1` / `G2` / `CP3` を書くか

**書くと判断しました。** ただし右端に「… CP1」のように併記する形にとどめ、
図の本文は「AIが設計する」「AIがテスト設計をする」という**動作の言葉**にしました。

図の直後に「名前を覚えなくても流れは追えます」と明記しています。
名称を完全に省くと `70_feature_loop.md` や `--status` の出力と対応が取れなくなるため、併記を選びました。

### 2. `ai_command` に実例（`claude,-p,...`）を載せるか

**載せないと判断しました。**

README に特定ベンダーのコマンド例を置くと、Claude 専用キットと読まれます。
代わりに、必要な条件を3点（非対話実行・モデルのコマンドライン指定・ファイル読み書き）で示し、
argv テンプレートの形だけを次のように書きました。

```text
ai_command = <AI CLI>,<非対話実行のオプション>,{instruction},<モデル指定のオプション>,{model}
```

記入例は `tools/README.md` と `70_feature_loop.md` の設定ブロックにあるため、そちらへリンクしています。

### 3. 「AIが判断できない事項を決める」を人間の責務に含めるか

**含めました。** ただし `RETURN` / `BLOCKED` という用語は出していません。

「人間の判断は CP1 と CP3 の2か所」とだけ書くと、**途中でAIが止まる場合があることが伝わらず、
「承認したらあとは自動」という誤解を生みます。** 用語なしで挙動だけを短く記載しました。

### 4. サンプル表を更新するか

**更新しないと判断しました。**

`docs/` には案内されていないサンプル3件（`cli_text_masker` / `cli_mask_rework` / `cli_uppercase_text`）が
ありますが、**扱いが M-7 で未決**です。Phase 4 で人間が判断してから反映します。
旧READMEの3行は現在も正しいため、そのまま維持しました。

### 5. `20_spec.md` を「人間が用意する」と書き切るか

**「人間が用意する」を基本としつつ、AIの補助を明記しました。**

`70_feature_loop.md` は「`20_spec.md` は人間側の成果物です。AIが作成を補助することはありますが、
確定させるのは人間です」としています。README で「人間が書く」とだけ書くと補助の余地を落とすため、
最初の一歩の手順に `prompts/create_feature_spec.md` での補助と「確定させるのは人間」を併記しました。
