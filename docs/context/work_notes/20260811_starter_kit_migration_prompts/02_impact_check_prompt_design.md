# 移行影響チェックpromptで重視したこと

## 目的

1段目promptの目的は、migrationそのものを実行することではない。

> 利用者固有の意図を新版への移行でsilent lossさせないために、移行前の状態を整理する

ことを目的とした。

そのため、このpromptは読み取り専用とした。

## A/B/Cを別々に比較する

基本となる入力は次の3状態である。

```text
A: 旧版スターターキット基準
B: 利用者カスタマイズ済み環境
C: 新版スターターキット基準
```

最初に、

```text
A → B
```

から利用者固有変更を抽出する。

その後、

```text
A → C
```

から新版の構造・ルール変更を調べる。

B→Cだけを見て変更の起源を推測しない。

## ファイル差分を利用者意図へ変換する

A→Bの変更行をそのままmigration単位にはしない。

変更を、

> 利用者が何を守ろうとして加えたのか

という意味単位へ変換し、U-itemとして追跡する。

同じファイル内でも目的が異なれば別itemとする。

逆に複数ファイルに同じ意図が重複していれば、一つの意味として扱える場合がある。

今回のfixtureでは最終的に13件の利用者意図へ分解された。

## 新版で「文章が消えた」だけでは未吸収としない

新版では、旧ファイルの責務が別の場所へ移る場合がある。

たとえば旧 `AGENTS.md` にあったルールが、新版では、

```text
docs/rules/core/
docs/rules/project/
prompts/
```

へ分割されている可能性がある。

そのため、

> 古い場所から文章が消えた

だけでは「新版に存在しない」と判断しない。

意味の移動先を追う。

## 「文章が残った」だけでも維持されたとしない

逆も同様である。

Git merge後に利用者の文章が残っても、新版でそのファイルが、

* 正本ではなくなった
* AIの通常参照対象から外れた
* task固有手順だけを置く場所になった

のであれば、利用者意図は実運用上失われる可能性がある。

そのためテキストの存在と、AIがその意味に従って動くことを分けて確認する。

## 吸収状況は強さまで見る

利用者意図は次のいずれかへ判定する。

* 吸収済み
* 部分吸収
* 未吸収
* 衝突
* 判断不能

吸収判定では文章の類似だけを使わず、

* 意味
* 拘束力
* 適用範囲
* 発動条件・頻度

を比較する。

たとえば利用者側が「常に確認する」としているものを、新版が「必要に応じて確認する」としている場合、完全吸収とは扱わない。

## ruleだけではなく実行導線を見る

新版にruleが存在しても、それだけで吸収済みとは判断しない。

必要に応じて、

```text
rule
 ↓
prompt
 ↓
template / 出力slot
 ↓
review
 ↓
人間確認
```

まで確認する。

ルールが存在していても、実際のtaskがそれを読まない、出力する場所がない、templateが対応していない場合は、利用者意図が実運用へ届かない可能性がある。

## 衝突はAIが勝手に解決しない

利用者ルールと新版方針が両立しない場合は、厳しい方を自動採用しない。

たとえば、

```text
利用者:
人間承認があれば外部ライブラリを追加できる

新版:
外部ライブラリを追加しない
```

という場合、AIが勝手にどちらかを削除しない。

「衝突」として人間へ返す。

STOPすること自体を失敗とは扱わない。

## contextの仕組みと履歴を区別する

新版にwork notes機能が追加された場合、

* work notes用rule
* prompt
* template
* README

などの仕組みはmigration対象になり得る。

一方、新版作者自身が過去に作ったwork note本文は利用者環境へ移す対象ではない。

新版に存在するファイルをすべてmigration対象にしない。

## silent lossチェックを最後に行う

抽出したすべてのU-itemについて、

* 吸収済み
* 部分吸収
* 未吸収
* 衝突
* 判断不能

のいずれかへ必ず追跡する。

どこにも登場しない利用者意図を残さない。

これを独立したsilent lossチェックとして出力する。

## Git操作は読み取り専用とした

fixture検証時には、現在のworktreeを変更せず、

* `git show`
* `git diff`
* `git ls-tree`
* `git grep`
* `git merge-base`
* 必要な読み取り専用確認

だけを利用する前提とした。

実移行は1段目の役割ではない。
