# 作業メモ: 統合後システム全体レビューの追加

## 目的

AI駆動開発スターターキットで、機能仕様IO単位の設計・実装を積み上げてシステム全体が組み上がった後に、現在の要件全体からシステム構造をもう一度見直せるようにする。

通常の設計・コード整合レビューや command/app 全体レビューとは別に、現在の feature 分割や実装構造そのものを正解として固定せず、全体最適とAI駆動開発への適合性を再評価する読み取り専用 prompt を追加する。

## 決定事項

- 機能仕様IO単位で人間とAIが考え、複数の機能仕様を束ねて作業する現在のスターターキット方式は維持する。
- 個々の機能・作業が妥当でも、全体が組み上がった後にはシステム構造を再考する余地があると考える。
- 統合後レビューでは、現在の feature 分割やコンポーネント境界を正解として固定しない。
- 「現在の要件を最初からすべて知っていても、同じ構造を選ぶか」を中心的な問いとする。
- 一般的な設計品質に加えて、AI駆動開発として以下を評価対象に含める。
  - 全体像の復元容易性
  - 変更範囲の局所性
  - AIが必要とするコンテキスト範囲
  - 試験・自己確認の局所性
  - AIによるレビュー容易性
  - 障害解析容易性
  - 構造上の境界と実際の責務の一致
- ゼロベースで別構造が考えられることと、現時点で変更すべきことを分けて報告させる。
- このレビューを `GO` / `条件付きGO` / `STOP` の正式ゲートにはしない。
- レビュー結果だけを根拠に、AIがリファクタリングや正式資料変更へ進まない。
- `review_command.md` へ統合せず、目的の異なる独立 prompt として追加する。
