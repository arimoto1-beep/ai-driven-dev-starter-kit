# docs/context/work_notes/（作業メモ）

このディレクトリは、作業単位のフォルダとREADME.mdを使って、作業の経緯・判断・手戻り・現在地を残すための置き場です。

このファイルは置き場の説明です。**ルール内容の正本ではありません。** 詳細は下記「位置づけとルールの正本」を参照してください。

---

## 目的

AIや人間が行った作業について、最終的に何を変更したかだけでなく、なぜその判断をしたか、途中で何が起きたか、どのような迷い・手戻り・見落としがあったか、採用しなかった案と理由、現在どこまで進んでいるか、次に何をすべきかを、後から確認できる形で残します。

## 保存単位

1日単位ではなく、**作業テーマ単位のフォルダ**です。

```text
docs/context/work_notes/YYYYMMDD_<short_name>/
```

`YYYYMMDD` は作業開始日、`<short_name>` は内容が識別できる短い名前です。同じテーマが複数セッション・複数taskにまたがる場合は、原則として同じフォルダへ記録します。

## 各作業フォルダの構成

各作業フォルダには、必ず `README.md` を置きます。README.md は、詳細記録の要約版ではなく、**入口・現在地・索引**です。

付随ファイル（`investigation.md`、`decisions.md` など）は、作業内容に応じた**自由形式**の Markdown です。ファイル名・種類・見出し構成を固定しません。

## 位置づけとルールの正本

このディレクトリの保存場所・保存単位・README形式・付随ファイルの扱い・作成条件・完了後の更新方法は、次を正本とします。**このREADMEでは再定義しません。**

- **`docs/rules/core/60_work_notes.md`** — 作業メモに共通する原則（プロジェクトに依存しない）
- **`docs/rules/project/60_work_notes.md`** — このスターターキット固有の保存方法と運用

README のひな形は `docs/templates/work_note_readme_template.md` です。

作業メモの新規作成・更新は `prompts/prepare_work_note.md` を使います。このtaskは作業メモ案を構成し、人間が内容を確認したうえで、リポジトリを操作できるAIならそのまま保存し、操作できないAIなら自己完結した反映指示を生成します。詳細な運用は `docs/rules/project/60_work_notes.md`、AIの保存権限は `docs/rules/project/50_ai_permissions.md` を正本とします。ここでは複製しません。

## 旧 `ai_work_logs/` との違い

`docs/context/ai_work_logs/`（旧AI作業ログ）とは**別方式**です。旧AI作業ログは、1タスク1ファイルの固定的な見出し構成で、AIが確認・更新した内容を記録する方式でした。凍結済みであり、新規作成しません（詳細は `../ai_work_logs/README.md`）。この作業メモは、1テーマ1フォルダで自由形式の付随ファイルを持ち、旧ログに代わる現在の記録方式です。

## 通常の context 整合性レビューとの関係

`docs/context/work_notes/` 配下は、通常の context 整合性レビュー（`prompts/review_context.md`）における**横断探索対象には含めません**。人間が参照を指示した場合や、現在の作業の引き継ぎ元・経緯確認として必要な場合に参照します。

## 正式仕様・ルールとの関係

作業メモは、正式仕様・設計・ルール・レビュー結果のいずれの正本でもありません。作業メモに書かれた決定事項が、そのまま正式資料へ反映されたことにはなりません。反映が必要な場合は、別の正式な変更作業として実施します。
