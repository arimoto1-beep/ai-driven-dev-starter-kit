# 作業メモ: AGENTS.mdの薄型化とルール体系分離

## 目的

肥大化していた `AGENTS.md` を薄い入口へ整理し、詳細ルールを `core / project / task` に分離する。

ただし、この作業メモでは「何を変更したか」の列挙よりも、完成した差分からは復元しづらい次の情報を優先して残す。

- 何に違和感があったか
- どこで迷ったか
- どの案を選んだか
- どの案を採用しなかったか
- なぜ判断を変えたか
- レビューをどう受け止めたか
- この作業から次に何を考えるようになったか

具体的な変更内容はGit差分と正式文書で確認できるため、ここでは判断の経緯を中心に記録する。

## 状態

完了

## 現在地

- `AGENTS.md` は薄い共通入口となり、詳細ルールは `docs/rules/core/` と `docs/rules/project/` へ分離された。
- taskごとに必要なルールは各promptの `## 必須参照ルール` で示す構造になった。
- 人向け文書とAIが従う正本ルールを分ける考え方が整理された。
- Opusレビューで出た指摘は一括採用せず、現在の設計意図と照らして人間側で採否を判断した。
- 実作業で使ってみた結果、ルール体系自体は機能する一方、正式文書やGitだけでは「なぜその形になったか」が残りにくいことが見えた。
- その不足が、後続の `docs/context/work_notes/` を作る直接の動機の一つになった。
- コミットは未実施。未コミット差分の整理は別作業。

## 決定事項

- `AGENTS.md` は詳細ルールの置き場ではなく、共通入口として扱う。
- 汎用原則はcore、スターターキット固有運用はproject、task固有手順はpromptへ分ける。
- 各taskが読むルール一覧は各promptの `## 必須参照ルール` を正本とする。
- 人向けREADMEやtutorialにルール本文を重複させすぎない。
- core / project / task が矛盾して読める場合、AIが勝手に優先順位を決めず人間判断へ戻す。
- Opus等のレビュー結果は、自動適用するのではなく、人間が採否を決める材料として使う。
- 作業メモでは、Gitから再現できる変更一覧より、判断・迷い・不採用理由を優先して残す。

## 未決事項

AGENTS.md薄型化とルール体系分離そのものについて、利用を妨げる未決事項はない。

未コミット差分のコミット単位は別作業。

## 次に行うこと

1. 新しいruleやpromptを追加するとき、core / project / task のどこに属するかを先に考える。
2. prompt変更時は完全性レビューで参照関係を確認する。
3. 正式文書に残らない判断経緯は `docs/context/work_notes/` に残す。
4. 未コミット差分のコミット単位は別途整理する。

## 完了後の追記

### 2026-08-08 コミット単位について

AGENTS.mdの薄型化・ルール体系分離とwork notes導入は、noteでは別の記事として扱うことにしたため、Gitのコミットも分ける案を検討した。

しかし現在の差分を実際に分類すると、複数の新規ruleや既存のREADME・promptに両方の変更が混在していた。

無理に分ける場合は、prompt数を一時的に現在と異なる状態へ書き換えたり、ai_work_logsをwork notes導入前の状態へ戻したりするなど、実際には存在しなかった中間状態を人工的に作る必要があった。

記事単位できれいにコミットを分けることより、各コミット時点でリポジトリが自然に整合していることを優先し、AGENTS.mdの薄型化・ルール体系分離とwork notes導入は1コミットにまとめることにした。

noteでは利用者向けの説明単位として、

1. AGENTS.mdを分離し、core / projectによって調整箇所を分かりやすくした話
2. AIとの作業で、Gitから消える「判断の跡」を残すwork notesを作った話

の2本に分けて扱う。
